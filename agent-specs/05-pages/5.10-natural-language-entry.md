# 5.10 AI 打字記帳（自然語言預填）

流程：`打一句話 -> POST /ai/interpret（DeepSeek）-> 重用單據覆核 model 預填交易表單 -> 人手核對 -> POST /ai/confirm 入帳`。

1. 入口喺新增交易表單（[§5.4](./5.4-transaction-form.md)）頂部嘅文字欄，唔另開 route；Dashboard 快速新增／掃描入口亦可帶同一句文字進入。文字只存記憶體，唔寫入 URL（唔可分享）。
2. 送出前 `trim`；空白唔可以送出；長度上限 500 字（前端先擋，唔會發請求）。解讀期間欄位下方顯示 progress，並可取消（遞增 generation 令舊回應失效，同 §5.6 一致）；離線唔排隊、唔假裝成功（見 [§8.3](../08-pwa.md)）。
3. 成功：後端回 `AiPreview`（`source: "text"`，`image_urls: []`）；前端**重用** [§5.6](./5.6-receipt-scan.md) 同一套 `previewToReviewValues`／`isLowConfidence`，將 `parsed` 填落表單（React Hook Form `reset`，並清空轉入帳戶）。
4. 填完即刻顯示「AI 已預填，請核對」提示，並**清空文字欄**（失敗／取消先保留原文方便重試）；**AI 一律唔會自動入帳**，要人手確認先送 `/ai/confirm`。
5. 低信心（< 0.6）或缺失欄位（金額／類型／日期／商戶）要明顯標示「需覆核」，跟 §5.6 一致；完全冇金額或冇交易意圖就當解讀失敗。
6. 商戶／分類對唔上時留空，唔亂猜；對唔到嘅商戶名帶入 autocomplete，讓用戶一按即可建立（同 §5.6）。
7. 失敗分兩種，處理一樣 —— 欄位下方 inline error + 重試 + 保留原文（重試會重新發請求）：(a) HTTP 錯誤（`502` DeepSeek 唔通／網絡）；(b) 「解讀唔到」：回傳 `status = partial`／`failed`，或 `parsed` 冇 `amount_cents`。
8. 入帳沿用 `POST /ai/confirm`（帶 `ai_import_log_id` + UUID `Idempotency-Key`），`source = ai`；成功後同 §5.4 一樣清 search 再開新交易詳情。
9. **MVP 只支援單筆**。偵測到多筆（例如「早餐 30 午餐 50」）時，後端只回第一筆並以 `status: "partial"` 提示，frontend 顯示「偵測到多筆，只預填第一筆，請分開記帳」，唔會自動拆單。

## 視覺

整個 AI 打字記帳區塊統一用**藍色系**，同品牌綠區分：卡底 `ai.bg`、邊框 `ai.border`、標題 `ai.fg`，區塊 `colorPalette="blue"` 令輸入框 focus ring、`解讀` 實色按鈕、`取消`／`重試` outline 按鈕 hover 全部變藍（唔好跟全域 `brand` 綠）。提示用淡藍 `status="info"`（低信心都一樣用藍色，靠文字講明，唔用琥珀色警告，避免同綠／藍撞色）。只有**錯誤**提示保留紅色 `status="error"`。
