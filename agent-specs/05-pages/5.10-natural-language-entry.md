# 5.10 AI 打字記帳（自然語言預填）

流程：`打一句話 -> POST /ai/interpret（DeepSeek，可拆多筆）-> 重用單據覆核 model -> 單筆預填表單／多筆開批量覆核 drawer -> 人手核對 -> POST /ai/confirm 入帳`。

1. 入口喺新增交易表單（[§5.4](./5.4-transaction-form.md)）頂部嘅文字欄，唔另開 route；Dashboard 快速新增／掃描入口亦可帶同一句文字進入。文字只存記憶體，唔寫入 URL（唔可分享）。
2. 送出前 `trim`；空白唔可以送出；長度上限 500 字（前端先擋，唔會發請求）。解讀期間欄位下方顯示 progress，並可取消（遞增 generation 令舊回應失效，同 §5.6 一致）；離線唔排隊、唔假裝成功（見 [§8.3](../08-pwa.md)）。
3. 成功：後端回 `AiPreview`（`source: "text"`，`image_urls: []`），多筆拆單結果放喺 `parsed_items`（每項 `{ parsed, suggested_category_id }`，最多 20 筆；`parsed`／`suggested_category_id` 為第一筆，向後兼容）。前端用 `previewItems(preview)` 正規化（冇 `parsed_items` 就由 `parsed` 合成單筆）。
    - **1 筆**：**重用** [§5.6](./5.6-receipt-scan.md) 同一套 `previewToReviewValues`／`isLowConfidence`，將第一筆填落表單（React Hook Form `reset`，並清空轉入帳戶）。
    - **≥ 2 筆**：唔預填表單，改為喺新增交易頁開**批量覆核 drawer**（`AiBatchReviewDrawer`，mobile 底部升起、desktop 右側滑入），並喺文字欄下方顯示「偵測到 N 筆交易，請逐筆覆核。」
4. 填完（單筆）即刻顯示「AI 已預填，請核對」提示，並**清空文字欄**（失敗／取消先保留原文方便重試）；多筆亦會清空文字欄。**AI 一律唔會自動入帳**，要人手確認先送 `/ai/confirm`。
5. 低信心（< 0.6）或缺失欄位（金額／類型／日期／商戶）要明顯標示「需覆核」，跟 §5.6 一致；完全冇金額或冇交易意圖（`parsed_items` 為空、或每筆都冇 `amount_cents`）就當解讀失敗。
6. 商戶／分類對唔上時留空，唔亂猜；對唔到嘅商戶名帶入 autocomplete，讓用戶一按即可建立（同 §5.6）。
7. 失敗分兩種，處理一樣 —— 欄位下方 inline error + 重試 + 保留原文（重試會重新發請求）：(a) HTTP 錯誤（`502` DeepSeek 唔通／網絡）；(b) 「解讀唔到」：回傳 `status = partial`／`failed`，或 `parsed_items` 冇有效金額。
8. 入帳沿用 `POST /ai/confirm`（帶 `ai_import_log_id` + UUID `Idempotency-Key`），`source = ai`。
9. **批量覆核 drawer**：每筆一張卡（藍色 `ai.bg`／`ai.border`），沿用同一套 `parsedItemToReviewValues`／`scanReviewSchema`／`reviewValuesToInput`；每筆可改（類型／金額／帳戶／商戶／分類／日期／備註）或刪除（最少保留 1 筆，刪到 0 會 disable 入帳並提示）。逐筆用各自嘅 `suggested_category_id` resolve 分類，唔會共用第一筆嘅建議。多筆時**新增交易 drawer 會先閂（返回交易列表）**，覆核 drawer 改掛喺交易 layout 層（`TransactionsLayout`），preview 經 `uiStore.pendingAiBatch`（非 persist）傳遞。`TransactionsLayout` 會等唔再停喺 `/transactions/new` 先開覆核 drawer，確保 **creation drawer 落畫之後先開**，唔會兩層同一 commit 交接（否則 focus 被搶會令覆核 drawer 即刻被 dismiss）；閂覆核 drawer（關閉鈕／ESC／點背景）只係收返覆核 drawer（用戶已經喺列表）。
10. 批量入帳：逐筆 `POST /ai/confirm`，**共用同一條 preview `id`**（`ai_import_log_id`），但**每筆一條獨立 UUID `Idempotency-Key`**（開 drawer 時生成、重試沿用）令重試唔會重複入帳。全部成功先 `bumpTransactionsRevision()` 並收返覆核 drawer；用戶已經喺交易列表，唔會另外跳走、保持當前 filter。
11. 任何一筆 confirm 失敗即停、保留 drawer 同顯示 inline error；重試由第一筆重新逐筆送，已成功嘅交易靠 idempotency key 變 no-op，唔會重複。

## 視覺

整個 AI 打字記帳區塊統一用**藍色系**，同品牌綠區分：卡底 `ai.bg`、邊框 `ai.border`、標題 `ai.fg`，區塊 `colorPalette="blue"` 令輸入框 focus ring、`解讀` 實色按鈕、`取消`／`重試` outline 按鈕 hover 全部變藍（唔好跟全域 `brand` 綠）。提示用淡藍 `status="info"`（低信心都一樣用藍色，靠文字講明，唔用琥珀色警告，避免同綠／藍撞色）。只有**錯誤**提示保留紅色 `status="error"`。
