# 5.4 新增／修改交易

第一步用 segmented control 選收入、支出、轉帳。欄位按類型改變：

| 欄位     | 收入／支出                                             | 轉帳                 |
| -------- | ------------------------------------------------------ | -------------------- |
| 金額     | 必填                                                   | 必填                 |
| 帳戶     | 必填                                                   | 必填（轉出）         |
| 轉入帳戶 | 不顯示                                                 | 必填且不可與轉出相同 |
| 商戶     | 可選 autocomplete                                      | 不顯示               |
| 分類     | 可選，按 kind 過濾                                     | 不顯示               |
| 日期時間 | 必填，預設現在                                         | 必填，預設現在       |
| 付款方式 | 可選                                                   | 可選                 |
| 備註     | 可選                                                   | 可選                 |
| 圖片     | 只讀：修改時顯示已有 URL preview（新增圖片經掃描流程） | 只讀                 |

- 商戶與分類在 md 以上並排（商戶在左、分類在右），mobile 疊住；商戶排在分類之前
- Merchant autocomplete debounce 300ms；輸入新名稱時可建立 merchant，再選回表單
- 選擇有 default category 的 merchant，會即時套用該分類（只在分類 kind 與目前 kind 相符時）；用戶仍可自行改分類
- 新增 merchant 時，如已選分類，會將該分類存為新 merchant 的 default category（下次再揀同一商戶會自動帶出）
- 商戶冇 default category 時，AI 自動分類建議會補位（見下節）
- Create 每次開表單產生 UUID 作 idempotency key；成功後同步更新相關 view，並清空列表 search（清除 filter、返回第一頁）再打開新交易詳情；Edit 成功保留原 search
- Edit 不可改變 `source`
- 離線時表單仍可填寫，但送出會呼叫 API 失敗並顯示錯誤（見 [§8.3](../08-pwa.md)）；banner 提示目前離線，不假裝成功、不排隊重試
- 離開 dirty form 前顯示確認
- 新增交易預設選取第一個帳戶；修改保留原有帳戶
- Desktop：右側 drawer；Mobile：底部 drawer（最高 92dvh）；直接進入 `/transactions/new`／edit URL 亦相同
- 表單 route 係 `TransactionsLayout` 嘅 child：列表留喺背景，唔會因為開／關表單而 remount
- 關閉新增 drawer 返回 `/transactions`（保留 search）；關閉修改 drawer 返回 `/transactions/:id`（即使表單仍在 loading，都用 URL 嘅 `id`，唔好因為 `transaction === null` 當新單咁返列表）

## AI 打字記帳入口

- 表單頂部提供文字欄，讓用戶打一句話預填（詳見 [§5.10](./5.10-natural-language-entry.md)）
- 解讀成功會 `reset` 已填欄位並提示核對；AI 唔會自動入帳，仍要人手確認
- 失敗保留原文，提供重試及「改用手動輸入」；空白或超過 500 字唔可以送出

## AI 自動分類建議

- 觸發：商戶欄或備註欄**失焦（blur）**時，若 (a) 目前 kind 係收入／支出、(b) 分類欄仍然空白、(c) 商戶或備註至少一樣非空白、(d) 商戶冇套用到 default category，就呼叫 `POST /ai/suggest-category`（帶 `kind` + `merchant_name` + `note`；空白嗰邊傳 `null`）
- 商戶有 default category（且同 kind 相符）時**唔會**發請求，deterministic 機制優先
- 成功而且 AI 對得上現有分類（`category_id` 非 null）：即時套用該分類，並喺「分類」欄標示藍色「AI 建議」badge；用戶可以照樣改分類（改咗即清走 badge）
- AI 揀唔到（`category_id` 為 `null`）或請求期間用戶已經改 type／揀咗分類：唔覆蓋任何嘢、唔顯示錯誤（當冇建議）
- 失敗（網絡／`502`）：喺分類欄下方顯示「AI 暫時建議唔到分類」+ inline「重試」按鈕，唔阻塞其他欄位、唔影響手動輸入（見 [§9](../09-feedback.md)）
- 用戶改商戶文字或改 kind 會令未完成／已套用嘅 AI 建議失效（清 badge；如新商戶有 default 就換返 default，否則清空分類）
- AI 建議**唔會**自動寫入做商戶 default category；要用戶自己改／揀過先會記低（同上面一般規則一致）
- 純建議、唔入帳、唔寫 DB、唔阻住送出；AI 生成內容一律用 `ai.*` 藍色系同品牌綠區分（見 [§2](../02-visual-design.md)）
